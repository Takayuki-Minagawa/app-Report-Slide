# KUMI かんたんガイド

KUMIは、MarkdownまたはDocument JSONから技術レポートとスライドを編集・確認するブラウザアプリです。初回表示は日本語・ライトモードです。ヘッダーのボタンで英語表示とダークモードに切り替えられ、選択はこのブラウザに保存されます。

## 1. 文書を始める

- 左下の **Markdownを開く** でMarkdownまたはDocument JSONを選びます。Markdown内のローカル画像を表示する場合は、画像ファイルも同時に選択します。
- 左下の **Report** または **Slide** では空の文書を始められます。
- Importした文書と画像はブラウザ内で扱われ、GitHub Pagesやこのリポジトリへ自動アップロードされることはありません。

## 2. 編集する

- **ビジュアル編集** で直接本文を編集し、書式バーから見出し、リスト、引用、表、数式、ページ／スライド区切りを追加します。
- **Markdown** タブでは原稿を直接編集します。編集後は **Markdownを適用**、またはヘッダーの **Markdown／JSON** 保存を実行してください。未適用の下書きがある間は、ビジュアル編集への切替を止めて内容の競合を防ぎます。
- 未保存の本文、章構成、未適用Markdown、取り込んだ画像は、このブラウザ内に復旧用として一時保存されます。次回開いたときに復元するか削除するかを選べます。これは端末内だけの補助機能なので、Markdown／JSON／プロジェクトZIPを原本として保存してください。
- 要素を選択すると、右の **Properties** でテーマ、目次、番号、参照ラベル、キャプション、図の幅・配置・代替テキストを設定できます。

## 3. 表を高度に編集する

- 表のセル内にカーソルを置くと、表専用ツールバーが現れます。行・列の追加／削除、先頭行のヘッダー切替、隣接セルの結合／分割ができます。
- 罫線は全体・外側・内側・各辺を選び、色、実線／破線／点線／二重線、太さを指定して引きます。**罫線を消す** に切り替えると、選んだ対象の線だけを消せます。
- 通常の表は標準Markdown表として保存されます。結合セル、個別罫線、複数段落を含む表はKUMIの可逆表ブロックとしてMarkdownに保存されます。外部Markdown編集器でそのブロックを変更せず、JSONまたはプロジェクトZIPも原本として保存してください。
- 完成プレビューとSlideのHTML出力は、結合セルと個別罫線を反映します。

## 4. 確認・保存する

- **完成プレビュー** ではReportをA4ページ、Slideを16:9スライドとして確認できます。明示した改ページ／スライド区切りごとにページを分けます。
- ヘッダーの **Markdown** または **JSON** でファイルを保存します。Document JSONはすべての編集構造を保持します。

### HTMLスライドを持ち出す

1. **Slide** 文書を作成・読み込みし、必要な位置にスライド区切りを入れます。
2. ヘッダーの **HTML** を押して、単一の `.html` ファイルを保存します。
3. 保存したファイルをブラウザで開き、**前へ／次へ**、←／→、Spaceで移動します。Home／Endで先頭／末尾へ移動できます。Fまたは **全画面** は対応ブラウザで利用できます。目次・相互参照を押すと対象スライドへ移動します。

スライド枠は画面に合わせて縮小・拡大されます。本文が枠に収まらない場合は内部をスクロールできますが、発表前に区切りを増やして調整してください。

数式フォントと取り込んだ画像はHTML内に埋め込まれます。外部URLの画像は通信が必要です。未取り込み画像のエラーが出た場合は、まず原稿をMarkdown／JSONで保存し、原稿と画像を同時に読み込んでから再出力してください。

HTMLは閲覧・発表専用で、KUMIへの再読み込みには対応していません。未適用のMarkdown下書きも出力対象ですが、原稿への適用や未保存表示の解除はしません。**編集用のMarkdown／JSONも別途保存してください。**

## 5. 表示と言語を変える

- 月／太陽のボタンでライトモードとダークモードを切り替えます。作業画面は配色を変えますが、文書の紙面は読みやすさのため白いままです。
- **EN** または **日本語** ボタンでアプリの操作文言を切り替えます。文書本文は利用者の内容であるため、自動翻訳は行いません。
- **ガイド** を開くと、アプリ内でも同じ要点を日英で確認できます。
- 画面幅が狭いときは、ヘッダーの文書パネル／Propertiesボタンから、左側の文書・章一覧と右側の設定を開けます。

## 6. 長いレポートを章に分ける

1. Reportを開き、左側の **現在のReportをプロジェクト化** を選びます。
2. **空の章を追加**、または **原稿を章として追加** で章を増やします。原稿はMarkdown／Document JSONを1件、画像は必要なものを同時に選びます。
3. 章名を選ぶとその章だけを編集できます。上へ／下へで順序を変え、**全体出力に含める** を外すと原稿を残したまま除外します。削除は確認後に行います。
4. **章の前で改ページ** と本文中の改ページでページを構成します。全体プレビューでは前へ／次へ、ページ選択、目次・参照リンクで移動できます。番号・参照は有効な章全体で計算します。
5. **プロジェクトZIPを保存** で構成・全章・画像を保存し、次回は **プロジェクトZIPを開く** で再開します。

ヘッダーの **章 Markdown／章 JSON** は編集中の章だけを保存します。**全体をMarkdown／JSONで出力** は有効な章を一つの文書に結合した出力です。どちらもZIP保存の代わりにはならず、プロジェクトの未保存表示は解除しません。

Markdown編集中は、適用または破棄してビジュアル編集に戻るまで章の構成を変更できません。章の構成変更はUndo対象外です。章の切替・削除では本文のUndo履歴をリセットします。端末内の復旧用コピーは未完了作業の再開を補助しますが、**タブを閉じる前にZIPを保存してください。** 詳細は [章別プロジェクトガイド](./report-projects.ja.md) を参照してください。

## 公開版を利用するときの注意

GitHub Pagesは公開サイトです。顧客情報、個人情報、社外秘、認証情報を含む文書や画像は読み込ませないでください。端末に保存したファイルやエクスポートしたファイルは、所属組織の規程に従って扱ってください。
