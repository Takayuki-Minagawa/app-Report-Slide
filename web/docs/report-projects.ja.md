# Report / Slideの章別プロジェクト

[English](./report-projects.en.md)

ReportまたはSlideを複数の章・デッキに分け、指定した順序で一つの資料として扱います。一つのプロジェクト内では文書種別を統一します。

## 操作と保存

| 操作                                 | 対象                                                                  |
| ------------------------------------ | --------------------------------------------------------------------- |
| 現在のReport / Slideをプロジェクト化 | 開いている資料を最初の章にする                                        |
| 原稿を章として追加                   | MD・JSON・編集HTML・文書ZIPを1件ずつ追加。必要な画像・元PDFも指定可能 |
| 章名を選択                           | その章だけを編集する                                                  |
| 上へ／下へ、全体出力に含める         | 章の順序と全体出力への含有を変更。除外章も保存する                    |
| 章 Markdown / JSON                   | 現在の章を保存。実効テーマと文献を含み、素材ファイルは別途必要        |
| 出力範囲「全体／編集中の章」         | HTML・PDF・Office・編集用ZIPの対象を切り替える                        |
| 全体をMarkdown / JSONで出力          | 含める章を結合。章構成や素材バイトは含まない                          |
| プロジェクトZIPを保存                | 全章（除外中も含む）、構成、画像、元PDF、部品、出典、補足を保存する   |

章名はナビゲーション用です。原稿のタイトルや見出しは自動変更しません。最後の章は削除できません。全章を除外した全体出力は空になります。章削除は確認後に行い、端末の元ファイルは削除しません。

## 4章のSlideを作る

1. Slideを開き、「現在のSlideをプロジェクト化」を選びます。
2. 「原稿を章として追加」を3回使い、既存の3デッキを追加します。同名の図やPDFも章ごとに分けて保存されます。
3. 章の順序と「全体出力に含める」を調整します。「全体のスライド目次」から別章のページへ移動して編集できます。
4. 出力範囲を「編集中の章だけ」にして単章HTML・PDF・PPTX・編集用ZIPを書き出します。「全体（含める章）」に戻すと全体版を作れます。再開用にはプロジェクトZIPを保存します。

Slideでは章の境界に必ずスライド区切りを入れます。「全体に章目次スライドを付ける」で含める章の目次を作れます。12章ごとに目次ページを分け、章順・含有変更後も移動先を再計算します。

共通テーマはプロジェクトで設定します。章ごとに「共通テーマを使用」または章専用テーマを選択でき、設定済みのページ別デザインは優先されます。手動画像配置、複合領域、表、グラフ、発表者ノート、公開補足はページとともに保持します。

「章内スライドの操作」でページの複製、前後移動、別章の末尾への移動ができます。複製は独立した要素IDと参照ラベルを持ちます。移動先にも図と元PDFを保存できます。「直前のスライド操作を取り消す」は本文・デザイン・補足をまとめて戻します。後から別の編集をした場合は無効になり、後続編集を上書きしません。章切替は本文の通常Undo履歴をリセットします。

## Reportのページと参照

Reportでは、最初の有効な章には自動改ページを入れず、以降は「章の前で改ページ」に従います。両形式とも、本文の先頭・末尾・連続した明示的な空ページを保持します。

番号とラベル参照は含める章全体から計算します。除外章への参照は未解決として警告します。Reportは既存の全章共通ラベルを維持します。Slideの新しいデッキを章として追加するときは、他章と衝突するラベルを新しいIDへ移し、追加したデッキ内部の参照も更新します。文献IDの衝突も区別し、同一文献への共有編集は関連する章へ反映します。

完成プレビューは明示したページを表示します。内容量に合わせた自動A4分割ではありません。

## ZIPの構造と互換性

ZIP直下の `project.json` に構成を保存し、`chapters/<章ID>/document.md` または `document.json` と章ごとの `assets` を格納します。`schemaVersion` は1、`type` はReportが `kumi-report-project`、Slideが `kumi-slide-project` です。旧ReportプロジェクトZIPを引き続き開けます。Slideの章には任意の `themeOverride`、全体の目次指定には `metadata.project_toc` を保存します。

各章はプロジェクトと同じ種別のMarkdownまたはDocument JSONです。Markdownで表せない構造は、保存時に同じディレクトリ内の衝突しないJSONへ切り替えます。編集HTML・文書ZIPを章に追加する際も、本文と再編集情報を取り込みます。

JSONの要素IDは章内で一意にします。別章の同じIDは全体表示・出力時に章IDを付けて区別します。Markdown再読込では再生成したIDにページデザインと補足を再対応させます。

素材パスは章の原稿からの相対パスです。新章の取り込み素材は専用ディレクトリへ保存します。結合MD / JSONの素材パスはZIP直下からの相対パスになるため、他のツールに持ち出す際は素材ディレクトリも必要です。単章HTMLと編集用ZIPには素材を同梱できます。外部URL画像はリンクのまま保持します。

## 制限

- 最大100章、ZIP内はディレクトリを含め300エントリ。ZIPは60MiB、展開後合計50MiB、原稿と構成ファイルは各5MiB、素材は各20MiBまでです。
- ZIPの非圧縮・Deflate方式に対応。暗号化、シンボリックリンク、ZIP外へのパス、重複名、安全でないパス、CRC不一致などは拒否します。
- 不足するローカル素材がある場合はZIP保存・読込を止めて案内します。元PDFもこの検査対象です。
- Markdown下書きは適用または破棄してから章を操作します。処理中に文書が変わった場合、古い非同期結果は採用しません。
- 全体出力にも文書形式のサイズ上限があります。章構成と除外章を含めて保持する原本はプロジェクトZIPです。
- クラウド保存、TeXのファイル取り込み互換、共同編集、ファイルシステムへの直接書き戻しはありません。端末内の復旧用コピーに加え、プロジェクトZIPを定期的に保存してください。
