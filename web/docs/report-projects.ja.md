# 章別プロジェクト

[English](./report-projects.en.md)

Reportを複数の原稿ファイルに分け、構成ファイルの順序で一つのレポートとして扱う機能です。Slideの章別管理やTeXの `\input` / `\include` 互換ではありません。

## 操作と保存の違い

| 操作                       | 対象                                                       |
| -------------------------- | ---------------------------------------------------------- |
| 章名を選択                 | その章だけをエディタに読み込む                             |
| 空の章／既存原稿を追加     | 見出しと空段落を持つ章、または原稿1件と画像を追加          |
| 上へ／下へ                 | 結合時の章順を変更                                         |
| 全体出力に含める           | 目次・番号・参照・結合出力の対象を切替。原稿は保持         |
| 章を削除                   | 確認後、プロジェクトから除去。端末の元ファイルは削除しない |
| 章 Markdown／章 JSON       | 現在の章だけを保存。画像や章構成は含まない                 |
| 全体をMarkdown／JSONで出力 | 有効な章を結合。除外原稿と構成ファイルは含まない           |
| プロジェクトZIPを保存      | 構成、全章（除外中も含む）、使用中の取り込み画像を保存     |

章の名前はナビゲーション用で、原稿内のタイトルや見出しを自動変更しません。プロジェクト名、テーマ、目次、節番号の設定は全体用です。各章のFront Matterは保持されますが、全体の表示にはプロジェクト設定を優先します。

全章を除外した場合、結合結果は空の本文になります。最後の章そのものは削除できません。構成操作はUndoの対象外です。章の切替・削除では本文のUndo履歴をリセットします。

## ページ・番号・参照

最初の有効な章の前には、自動の改ページを入れません。それ以降は各章の「章の前で改ページ」に従います。本文に記した明示的な改ページ（先頭・末尾・連続した空ページも含む）はそのまま保持します。

節番号、図・表・式の番号、目次とラベル参照は有効な章全体から計算します。章の順序・含有を変えると再計算します。重複・未解決ラベルは警告され、ラベルを勝手に書き換えることはありません。除外した章を参照すると未解決になります。

プロジェクトのプレビューは明示的に区切った1ページだけを描画します。ページ選択や目次・参照リンクで移動できます。A4の高さに応じて本文を自動分割する機能ではなく、一つの章やページに非常に多くの内容を入れるとその部分の描画は重くなります。

## ZIPの構造

```text
report.kumi.zip
├── project.json
└── chapters/
    ├── chapter-.../
    │   ├── document.md
    │   └── assets/image-1.svg
    └── chapter-.../
        └── document.json
```

構成ファイルの例です。`chapters` 配列が出力順です。

```json
{
  "schemaVersion": 1,
  "type": "kumi-report-project",
  "metadata": {
    "title": "調査レポート",
    "theme": "latex",
    "toc": true,
    "number_sections": true
  },
  "chapters": [
    {
      "id": "intro",
      "title": "はじめに",
      "file": "chapters/intro.md",
      "enabled": true,
      "pageBreakBefore": false
    }
  ]
}
```

ZIPを展開して原稿や構成ファイルを編集し、再圧縮して読み込むこともできます。`project.json` をZIPの直下に置いてください。各章はReport形式のMarkdown／Document JSONです。Markdownで表現できない章は、保存時に同じディレクトリ内の、他のファイル名と衝突しない `.json` に切り替えて保持します。

Markdownの要素IDは再読込時に生成されるため、相互参照にはラベルを使います。JSON章の要素IDは各章内で一意にしてください。別の章では同じ要素IDを使用でき、章間でコピー・貼り付けもできます。全体の表示・結合出力時だけ章IDを付けて区別し、章の原稿IDは保持します。ラベルは全章で共通なので、重複したラベルは別途修正してください。

ローカル画像パスは章の原稿ファイルからの相対パスです。`../images/a.png` のようにZIP内で共有できますが、ZIPの外へは移動できません。アプリ内で新しい章を追加すると、取り込んだ画像は章専用の `assets` に配置します。同名の画像でも別章と混同しません。

結合したMarkdown／JSON内の画像パスは、ZIPの直下からの相対パスです。画像付きの結合文書を他のツールで扱う場合は、ZIPを展開した直下に結合文書を置き、画像のディレクトリも一緒に持ち出してください。外部URL画像はダウンロード・同梱せず、元のリンクを保持します。ローカル画像が不足する場合、ZIP保存・読込を止めて案内します。

## 制限と注意

- 最大100章、ZIP内はディレクトリを含め300エントリまで。
- ZIPの非圧縮・Deflate方式に対応します。暗号化やシンボリックリンクは対象外です。サイズ・ヘッダー・CRCの不一致を検知した場合は読み込みません。
- ZIPファイルは60MiB、展開後合計は50MiBまで。原稿と構成ファイルは各5MiB、画像は各20MiBまで。
- 絶対パス、ZIP外へのパス、重複ファイル名（大文字小文字の違いも含む）、Windows予約名、安全でないパス、構成に無関係なファイルは拒否します。
- Markdown下書きの適用・破棄前には章を変更できません。ZIPの処理中に編集した場合、古い結果を採用しません。編集後に再度保存してください。
- クラウド保存はありません。未保存の作業は端末内の復旧用コピーとして一時保存されますが、保存したZIPが再開用の原本です。ブラウザの終了警告や復旧用コピーだけに頼らず、定期的に保存してください。
- PDF、ReportのHTML、自動A4組版、ファイルシステムへの直接書き戻し、共同編集は対象外です。
