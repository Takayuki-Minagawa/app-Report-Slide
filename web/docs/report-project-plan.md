# 章別レポート管理の作業計画

## 目的と範囲

長いレポートを章別の原稿ファイルに分けて編集し、構成ファイルの順序で一つのレポートとして扱えるようにする。既存の単一 Markdown / JSON 文書とスライド機能、GitHub Pages の静的・ローカル完結構成を維持する。

- 構成ファイルと章別原稿、読み込んだ画像を ZIP に保存し、再読込できる。
- 現在のレポートからプロジェクトを作成し、空の章や既存原稿を追加できる。
- 章の切替、名称変更、並べ替え、出力対象からの除外、確認付き削除を行える。
- 除外した章も保存する。削除はプロジェクト内だけに作用し、端末の元ファイルは削除しない。
- 全体の目次・節番号・図表数式番号・相互参照を共通化し、結合したレポートを Markdown / JSON で出力できる。
- エディタは選択した章だけを開く。プロジェクトのプレビューはページを切り替えて表示し、大量のページを同時に描画しない。
- 章の先頭の改ページ設定と既存の改ページノードを使う。用紙サイズに応じた自動組版・自動改ページは対象外。
- 日本語・英語の画面と簡易マニュアルを更新する。

## 設計上の約束

- 未適用の Markdown は、章の切替や構成変更の前に適用・破棄を要求する。
- 個別の章の保存と全体の保存を区別し、未保存の構成変更を隠さない。
- 章のメタデータとラベルを保持する。全体の表示設定にはプロジェクト設定を使う。
- 重複ラベルや存在しない参照は診断として表示し、勝手に書き換えない。
- 不正な構成、パスの逸脱、重複ファイル、過大な展開サイズを検証する。
- 遅れて完了した読込・保存で途中の編集を上書きしない。画像 URL は所有元の終了時に解放する。
- 外部サービスへの文書送信、クラウド保存・認証・共同編集は追加しない。

- [x] `main` の状態を確認し、`codex/report-projects` ブランチを作成する。
- [x] 既存アプリと適用される手順を確認し、この計画を作成する。
- [x] モデル、結合・参照、ZIP 入出力を実装し、単体テストで検証する。
- [x] 章管理 UI と編集状態・画像管理を接続する。
- [x] ページ切替プレビュー、章ごとの保存、全体出力を実装する。
- [x] 日本語・英語の文言、README、簡易マニュアル、形式仕様を更新する。
- [x] 単体・統合・E2E テスト、書式、Lint、型検査、通常ビルドと Pages ビルドを実行する。
- [ ] コミット・プッシュし、`main` 向けの PR を作成する。
- [ ] PR 作成後、サブエージェントに読み取り専用の独立レビューを依頼する。
- [ ] 修正・再テスト・再レビューを繰り返し、CI とマージ可能性を確認する。

## 完了条件

章別ファイルの編集と保存・再読込、全体出力、除外・削除・並べ替え、章間参照、未保存状態がテストで確認でき、既存機能の回帰がないこと。PR の必須チェックが成功し、解消すべき指摘がなく、マージ可能となったところで終了する。この作業では PR をマージせず、`main` へプッシュしない。
