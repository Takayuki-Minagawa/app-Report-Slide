# Reportの表紙・章番号・目次

Reportの **プロパティ → 報告書の構成** で、表紙、章・節番号、図表・式番号、目次をまとめて設定できます。編集後は **報告書の構成を適用** を押し、完成プレビューで確認してください。未適用のMarkdown下書きがある間は変更できません。

本文の1字下げや段落ごとの例外は [ページ設定ガイド](./page-settings.ja.md) を参照してください。

## 表紙を付ける

1. **表紙を付ける** を有効にします。
2. 報告書の題名、副題、著者、提出日、所属、提出先、報告書番号を入力します。
3. **報告書の構成を適用** を押します。副題や所属などの空欄は表示しません。

表紙は設定から生成され、編集用の本文へ見出しや改ページを挿入しません。表紙の題名は本文の章番号や目次に含まれません。表紙を無効にしても本文を削除することはありません。

## 章・節と図表・式の番号

**章・節番号を表示** を有効にし、**章・節の番号書式** を選びます。

| 設定     | H1見出し     | H2見出し | H3見出し |
| -------- | ------------ | -------- | -------- |
| 階層番号 | 1、2         | 1.1、1.2 | 1.1.1    |
| 章番号   | 第1章、第2章 | 1.1、1.2 | 1.1.1    |

章の境界は原稿のH1（`# 見出し`）です。章別プロジェクトの章ファイル名やナビゲーションの章名を、自動で本文へ追加することはありません。章を始める位置には自分でH1を置きます。章番号を選ぶだけでは改ページを追加しないため、必要な場合は明示改ページまたはプロジェクトの **章の前で改ページ** を指定してください。

**図・表・式の番号** は次から選びます。

- **文書全体の通し番号**：図1、図2、表1、式1のように、それぞれ独立して採番します。
- **章ごと**：図1.1、図1.2、図2.1のように、H1を境界として種類ごとの番号を振り直します。H1より前に置いた要素は図0.1などになります。

見出し番号を非表示にしても、章別の図表・式番号の章区分は維持します。個別のH1に `numbered=false` を指定した場合は、そのH1を章として数えず、図表・式のカウンターもリセットしません。

図表・式の章別番号を使う場合は、見出しが「階層番号」でも同じH1カウンターで採番します。H1より前のH2は0.1になり、見出し番号を非表示にした通常のH1も章数へ含めます。これにより、後から個別に表示したH1番号と図表の章番号が一致します。

図表・式は、キャプションまたは参照ラベルを持つ場合に既定で採番します。要素ごとの `numbered=true`／`false` で変更できます。番号は原稿に固定せず、並べ替えや章の除外後に再計算します。相互参照には `[@fig:result]` などのラベルを使ってください。

## 付録を始める

番号書式を **章番号** にし、最初の付録となるH1を選択します。要素の設定で **この章から付録として採番** を有効にして **属性を適用** を押すと、そのH1から付録A、次のH1は付録Bと表示されます。

```markdown
# 補足データ

{#app:data appendix=true}

## 測定条件

付録内の節はA.1と表示されます。
```

章別の図表・式番号も、付録では表A.1、式A.1などになります。付録指定は最初のH1以降に続き、後続の `appendix=false` で通常章へ戻す動作はありません。`appendix=true` をH2以下に保存しても、付録の開始にはなりません。また、番号書式が「階層番号」の間は付録指定を表示に適用しません。

## 目次・図目次・表目次

**報告書の構成** で **見出しの目次を付ける** を有効にし、**目次に含める見出し** をH1〜H6から選びます。H2までならH1とH2を載せ、H3以降は載せません。

特定の見出しを外すには、その見出しを選び、**この見出しを目次に含める** を解除して **属性を適用** を押します。Markdownでは次のように記述します。

```markdown
## 作業用の補足

{toc=false}
```

この操作はその見出しの目次掲載だけを変えます。本文・番号・相互参照は残ります。配下の見出しを一括で除外する設定ではありません。

**図目次を付ける**・**表目次を付ける** も個別に選べます。採番された図・表だけを対象とし、`numbered=false` の要素は載せません。すべての目次には本文へのリンクを付けます。項目がない目次は本文内では省略し、独立目次ページでは「項目なし」を表示します。

**目次・図表目次を独立ページにする** を有効にすると、選んだ目次を表紙の後・本文の前にまとめます。見出し目次・図目次・表目次をすべて無効にした場合は、独立目次ページを生成しません。独立ページを使わない場合は、本文の最初に目次を表示します。

### 実際のページ番号を載せる

1. **目次に実際のページ番号を表示** を有効にし、**報告書の構成を適用** を押します。Markdownでは `report_settings.toc_page_numbers: true` を指定します。
2. 完成プレビューの「用紙に合わせて組版しています…」が終わるまで待ちます。設定した用紙・余白・文字サイズで自動改ページし、目次・図目次・表目次に参照先の実際の本文ページ番号を表示します。
3. 本文や用紙設定を変更すると、改ページ位置とページ番号を再計算します。章別プロジェクトでは有効な章を結合した文書が対象です。

表紙と独立目次は、複数の紙面になってもページ番号を表示しません。本文の最初の紙面を1とし、自動改ページ後も2、3…と続けます。目次の番号は、この本文ページ番号です。独立目次を使わず本文冒頭に置いた目次は、本文ページに含まれます。

この設定は既定で無効です。無効な場合は従来どおりリンク付きの目次となり、目次にページ番号は表示しません。本文プレビューの番号は原稿の明示改ページによる論理ページで、自動分割後の物理ページ番号とは異なります。

## ページと出力

実ページ番号を有効にしたReportは、完成プレビュー、HTML、印刷用HTML、ヘッダーの直接PDFで共通のページ組版を使います。用紙に収まるように本文を改ページしてから、目次と本文のページ番号を確定します。

表紙や独立目次があり、本文に空段落・発表者ノートしかない場合は、余分な空本文ページを作りません。原稿に明示した先頭・末尾・連続した改ページによる空ページは保持します。

| 出力                          | 実ページ番号を有効にした場合                                                           |
| ----------------------------- | -------------------------------------------------------------------------------------- |
| 完成プレビュー・HTML          | 共通の組版で自動改ページし、目次と本文に実ページ番号を表示                             |
| 印刷用HTML／ブラウザーPDF保存 | 組版済みの紙面を印刷。文字・数式・表を検索可能なPDFとして保存できる                    |
| ヘッダーの直接PDF             | 同じ組版済みの紙面を画像として保存。文字の選択・検索は不可                             |
| Word                          | Wordで組版し、目次のページ参照フィールドを更新。HTMLとは改ページ位置が異なる場合がある |

### 印刷するとき

1. 組版完了後に **印刷／PDF保存** を押します。組版中や失敗時はアプリ／出力HTMLの印刷ボタンを使えません。直接PDFも組版に失敗した場合は出力を止めます。
2. 印刷ダイアログの用紙サイズ・向きを、KUMIのページ設定と同じにします。倍率は **100%** にします。
3. ブラウザーが追加する **ヘッダーとフッター** を無効にし、余白を追加しない設定にします。文書の余白と本文ページ番号は紙面に含まれています。
4. 印刷プレビューで各紙面の収まりを確認し、印刷またはPDF保存します。

印刷ダイアログで別の用紙や倍率に変えた場合、目次番号と印刷後のページの一致は保証できません。用紙を変える場合はKUMIのページ設定を変更し、組版をやり直してください。

長い表はページをまたいで配置しますが、用紙に収まらない行・結合セル・画像などがある場合はエラーを表示します。表を分ける、画像を小さくする、文字サイズや余白を調整するなどして再試行してください。エラーになった紙面や未計算の目次番号を完成版として印刷しないでください。

### Wordでページ番号を更新する

Word出力の目次・図目次・表目次には、実ページ番号が有効な場合に `PAGEREF` フィールドを入れます。ファイルをWordで開く際にフィールドの更新を許可してください。番号が空欄、または編集後に古い場合は、文書全体を選択して **F9**（環境によっては **Fn＋F9**）、またはWordの **フィールドの更新** を実行します。フィールドを計算しない他のビューアーでは番号が空欄になることがあります。

Wordは表紙・独立目次・本文をセクションで分け、本文ページ番号を1から始めます。目次のページ番号以外の、見出し・図表番号、目次の項目、参照文字列は出力時点の値です。それらはWordで本文を変更しても自動では再採番されません。数式はLaTeXテキスト、グラフはデータ表となる既存の出力制約もあります。

### オフラインでの利用

実ページ番号を有効にしたHTMLには、組版用のPaged.jsとフォントを同梱します。その分HTMLの容量と初回の表示時間が増えますが、組版のためのCDN接続やネットワーク通信は不要です。画像も取り込んでHTML内に埋め込んでください。外部URLの画像を残した場合、その画像の読込には通信が必要です。

Paged.jsはHTML/CSSをブラウザー内で用紙ごとのページへ分割します。仕組みは公式の [How Paged.js works](https://pagedjs.org/en/documentation/4-how-paged.js-works/)、用紙・余白・改ページの考え方は [Web design for print](https://pagedjs.org/en/documentation/5-web-design-for-print/) を参照してください。

## 保存形式とMarkdown

構成設定はMarkdownのFront Matterの `report_settings`、またはDocument JSONのmetadataへ保存します。章別プロジェクトでは全章共通の設定として扱い、有効な章を結合した順序で番号と参照を計算します。保存するのは設定と原稿で、計算したページ番号を原稿には固定しません。再表示・再出力時に番号を計算し直します。章構成を含む原本はプロジェクトZIPで保存してください。

`report_settings` の各キーは任意です。未指定なら従来どおり表紙なし、階層番号、図表・式は通し番号、目次深さH6、独立目次なし、図目次・表目次なしになります。`toc_page_numbers` も未指定時は `false` で、従来の表示を保ちます。既存文書を開くだけで新しい構成へ変更しません。SlideではこれらのReport用設定を表示に適用しません。

```yaml
---
type: report
title: 技術報告書
subtitle: 調査結果
author: 作成担当
date: '2026-11-06'
number_sections: true
toc: true
report_settings:
  cover: true
  heading_numbering: chapter
  caption_numbering: chapter
  toc_depth: 2
  toc_page: true
  toc_page_numbers: true
  list_figures: true
  list_tables: true
  affiliation: 技術部
  recipient: レビュー担当
  report_number: SAMPLE-001
---
```

見出しの `appendix`／`toc` 属性と `report_settings` はKUMIの拡張です。一般のMarkdownビューアやTeX文書クラスとの完全な互換を意味しません。本文の変更を元に戻すUndoとは別に、文書設定は設定パネルで変更してください。

## サンプル

[報告書構成サンプル](../examples/example-report-structure.md)と、その図に使う[同梱アイコン](../public/favicon.svg)を **HTML・原稿を開く** で一緒に選択します。実ページ番号を有効にしてあり、表紙、独立した各目次、2つの通常章、付録、目次から除外した見出しを確認できます。本文を増やしたり余白を変えたりして、目次番号の更新を試せます。

ローカル一括出力でも確認できます。実ページ番号の計算にはChromiumが必要なので、初回は `npm --prefix local_renderer run install:browser` を実行します。リポジトリルートからの出力例です。

```sh
node local_renderer/render.mjs --input web/examples/example-report-structure.md --assets-dir web/public --output-dir /tmp/kumi-report-structure
```

## 今後の拡張

現在の自動改ページと実ページ番号に続き、長表・孤立行の細かな制御、柱、脚注のページ下端配置を検討します。Report全体の役割別共通スタイル、本文引用と参考文献一覧、文献取込も後続項目です。通常の検証はローカルで行い、GitHub Actionsを通常CIには使いません。
