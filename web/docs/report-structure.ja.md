# Reportの表紙・章番号・目次

Reportの **プロパティ → 報告書の構成** で、表紙、章・節番号、図表・式番号、目次をまとめて設定できます。編集後は **報告書の構成を適用** を押し、完成プレビューで確認してください。未適用のMarkdown下書きがある間は変更できません。

本文の1字下げや段落ごとの例外は [ページ設定ガイド](./page-settings.ja.md) を参照してください。

## 表紙を付ける

1. **表紙を付ける** を有効にします。
2. 報告書の題名、副題、著者、提出日、所属、提出先、報告書番号を入力します。
3. **報告書の構成を適用** を押します。副題や所属などの空欄は表示しません。

表紙は設定から生成され、編集用の本文へ見出しや改ページを挿入しません。表紙の題名は本文の章番号や目次に含まれません。表紙を無効にしても本文を削除することはありません。

## 章・節と図表・式の番号

**章・節番号を表示** を有効にし、**章・節の番号書式** を選びます。

| 設定     | H1見出し     | H2見出し | H3見出し |
| -------- | ------------ | -------- | -------- |
| 階層番号 | 1、2         | 1.1、1.2 | 1.1.1    |
| 章番号   | 第1章、第2章 | 1.1、1.2 | 1.1.1    |

章の境界は原稿のH1（`# 見出し`）です。章別プロジェクトの章ファイル名やナビゲーションの章名を、自動で本文へ追加することはありません。章を始める位置には自分でH1を置きます。章番号を選ぶだけでは改ページを追加しないため、必要な場合は明示改ページまたはプロジェクトの **章の前で改ページ** を指定してください。

**図・表・式の番号** は次から選びます。

- **文書全体の通し番号**：図1、図2、表1、式1のように、それぞれ独立して採番します。
- **章ごと**：図1.1、図1.2、図2.1のように、H1を境界として種類ごとの番号を振り直します。H1より前に置いた要素は図0.1などになります。

見出し番号を非表示にしても、章別の図表・式番号の章区分は維持します。個別のH1に `numbered=false` を指定した場合は、そのH1を章として数えず、図表・式のカウンターもリセットしません。

図表・式は、キャプションまたは参照ラベルを持つ場合に既定で採番します。要素ごとの `numbered=true`／`false` で変更できます。番号は原稿に固定せず、並べ替えや章の除外後に再計算します。相互参照には `[@fig:result]` などのラベルを使ってください。

## 付録を始める

番号書式を **章番号** にし、最初の付録となるH1を選択します。要素の設定で **この章から付録として採番** を有効にして **属性を適用** を押すと、そのH1から付録A、次のH1は付録Bと表示されます。

```markdown
# 補足データ

{#app:data appendix=true}

## 測定条件

付録内の節はA.1と表示されます。
```

章別の図表・式番号も、付録では表A.1、式A.1などになります。付録指定は最初のH1以降に続き、後続の `appendix=false` で通常章へ戻す動作はありません。`appendix=true` をH2以下に保存しても、付録の開始にはなりません。また、番号書式が「階層番号」の間は付録指定を表示に適用しません。

## 目次・図目次・表目次

**報告書の構成** で **見出しの目次を付ける** を有効にし、**目次に含める見出し** をH1〜H6から選びます。H2までならH1とH2を載せ、H3以降は載せません。

特定の見出しを外すには、その見出しを選び、**この見出しを目次に含める** を解除して **属性を適用** を押します。Markdownでは次のように記述します。

```markdown
## 作業用の補足

{toc=false}
```

この操作はその見出しの目次掲載だけを変えます。本文・番号・相互参照は残ります。配下の見出しを一括で除外する設定ではありません。

**図目次を付ける**・**表目次を付ける** も個別に選べます。採番された図・表だけを対象とし、`numbered=false` の要素は載せません。すべての目次には本文へのリンクを付けますが、印刷後のページ番号は付けません。項目がない目次は本文内では省略し、独立目次ページでは「項目なし」を表示します。

**目次・図表目次を独立ページにする** を有効にすると、選んだ目次を表紙の後・本文の前にまとめます。見出し目次・図目次・表目次をすべて無効にした場合は、独立目次ページを生成しません。独立ページを使わない場合は、本文の最初に目次を表示します。

## ページと出力

表紙と独立目次にはページ番号を表示せず、本文を1から始めます。本文のプレビュー番号は、原稿の明示改ページによる論理ページです。内容が長く、印刷時に複数の紙面へ分割されても、HTML／直接PDFで物理ページごとの番号を再計算する保証はありません。Wordは本文セクションのページ番号を1から始め、Word側でページ番号を更新します。

表紙や独立目次があり、本文に空段落・発表者ノートしかない場合は、余分な空本文ページを作りません。原稿に明示した先頭・末尾・連続した改ページによる空ページは保持します。

| 出力                          | 表紙・構成の扱い                                                         |
| ----------------------------- | ------------------------------------------------------------------------ |
| 完成プレビュー・HTML          | 表紙、目次、章番号、図表番号、参照を設定から生成                         |
| 印刷用HTML／ブラウザーPDF保存 | 同じ構成で印刷。長い内容の分割はブラウザーに依存                         |
| ヘッダーの直接PDF             | 同じ構成を紙面画像として保存。文字検索は不可                             |
| Word                          | 表紙・独立目次・本文をセクションで分け、目次・参照は内部リンクとして保存 |

Wordの見出し・図表番号、目次の文言、参照文字列は出力時点の値です。Word上で内容を変更した後の番号再計算は自動ではありません。数式はLaTeXテキスト、グラフはデータ表となる既存の出力制約もあります。

## 保存形式とMarkdown

構成設定はMarkdownのFront Matterの `report_settings`、またはDocument JSONのmetadataへ保存します。章別プロジェクトでは全章共通の設定として扱い、有効な章を結合した順序で番号と参照を計算します。章構成を含む原本はプロジェクトZIPで保存してください。

`report_settings` の各キーは任意です。未指定なら従来どおり表紙なし、階層番号、図表・式は通し番号、目次深さH6、独立目次なし、図目次・表目次なしになります。既存文書を開くだけで新しい構成へ変更しません。SlideではこれらのReport用設定を表示に適用しません。

```yaml
---
type: report
title: 技術報告書
subtitle: 調査結果
author: 作成担当
date: '2026-11-06'
number_sections: true
toc: true
report_settings:
  cover: true
  heading_numbering: chapter
  caption_numbering: chapter
  toc_depth: 2
  toc_page: true
  list_figures: true
  list_tables: true
  affiliation: 技術部
  recipient: レビュー担当
  report_number: SAMPLE-001
---
```

見出しの `appendix`／`toc` 属性と `report_settings` はKUMIの拡張です。一般のMarkdownビューアやTeX文書クラスとの完全な互換を意味しません。本文の変更を元に戻すUndoとは別に、文書設定は設定パネルで変更してください。

## サンプル

[報告書構成サンプル](../examples/example-report-structure.md)と、その図に使う[同梱アイコン](../public/favicon.svg)を **HTML・原稿を開く** で一緒に選択します。表紙、独立した各目次、2つの通常章、付録、目次から除外した見出しを確認できます。

ローカル一括出力でも確認できます。リポジトリルートから実行する例です。

```sh
node local_renderer/render.mjs --input web/examples/example-report-structure.md --assets-dir web/public --output-dir /tmp/kumi-report-structure
```

## 今後の拡張

現在の機能に続き、見出しと次段落の同一ページ配置、長表・孤立行の制御、物理ページ番号と柱、脚注のページ下端配置を検討します。これらはページ組版方式の検証を先に行います。Report全体の役割別共通スタイル、本文引用と参考文献一覧、文献取込も後続項目です。通常の検証はローカルで行い、GitHub Actionsを通常CIには使いません。
