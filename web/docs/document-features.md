# LaTeX風の文書機能

## 使い方

1. Navigatorで見出し・図・表・ブロック数式を選択します（表内の本文選択でも表を選択できます）。
2. Propertiesで「参照ラベル」「キャプション」「番号付け」を設定し、「属性を適用」を押します。図は幅・配置・代替テキストも編集できます。
3. 参照を置く本文位置を選び、Propertiesの「参照先ラベル」に入力して「参照を挿入」を押します。
4. 文書の「目次」「節番号」を必要に応じて有効にします。完成プレビューでは番号・リンクを自動生成します。
5. 「改ページ」または「スライドを区切る」で、選択中の最上位ブロックの後ろに区切りを追加します。プレビューは全ページを縦に表示します。

未適用Markdown下書きがある間、Propertiesなどの文書変更操作は無効です。先に適用するか破棄してください。参照先未定義・ラベル重複は警告だけで、原稿を消したり保存を止めたりしません。本文・要素属性の変更はUndo/Redo対象ですが、テーマ・目次・節番号・スライド番号の文書設定は対象外です。

## Markdown構文

属性は対象ブロックの直後に、独立した1行で指定します。キーの重複・未知キー・不正値は読込エラーとなり、適用前の原稿を保持します。文字として書く場合は先頭の記号をバックスラッシュでエスケープしてください。

```markdown
# 解析概要

{#sec:overview}

図 [@fig:response] と式 [@eq:motion] を参照する。

![応答](assets/response.svg)
{#fig:response width=65% align=right caption="最大応答" numbered=true}

$$
M\ddot{x}+C\dot{x}+Kx=F(t)
$$

{#eq:motion caption="運動方程式"}

| 項目     | 値      |
| -------- | ------- |
| 最大変位 | 24.5 mm |

{#table:result caption="結果一覧"}

::: pagebreak
:::
```

- `label`は英字で始まる128文字以内の英数字・`:`・`.`・`_`・`-`。任意の名前を使えます。`#fig:name`と`label="fig:name"`は同じ意味です。
- 参照の正式な記法は`[@label]`です（裸の`@label`は通常の本文）。既存Markdownリンク・コード・数式の中は参照として解釈しません。
- `caption`はプレーンテキスト。引用符・改行・バックスラッシュにはJSON文字列のエスケープ（`\"`、`\n`、`\\`）を使います。
- 図・表・式は別々のカウンター。`numbered=true`は番号を有効、`false`は無効にします。省略時はキャプションまたはラベルがある要素だけを採番し、旧文書の見た目を維持します。
- 見出しはFront Matterの`number_sections: true`で採番します。個別属性`numbered=true`／`false`は文書設定を上書きします。飛ばした上位階層は1で補完します。除外した要素はカウンターを消費しません。
- `toc: true`で最初のページに目次、`slide_number: false`でスライド番号を非表示にします。
- スライド区切りは`::: slidebreak`と次行の`:::`。`pagebreak`／`slidebreak`はどちらの文書種別でも明示的区切りとして保持します。
- 区切りは文書直下のみ。先頭・末尾・連続する区切りは空ページを作ります。従来の`---`は水平線のままです。

内部`nodeId`は編集用、`label`は安定した参照用です。Markdown再読込でnodeIdが変わってもlabelは保持され、番号は都度再計算します。番号自体は保存しません。

## 脚注

ツールバーの **脚注を挿入** でカーソル位置に脚注を追加し、右のPropertiesで本文を編集して **脚注を更新** を押します。編集画面の番号を選ぶと、同じ場所で再編集できます。番号は文書順に自動で付き、完成プレビューとHTML出力ではそのページ／スライドの末尾に一覧表示します。

```markdown
最大変位は 24.5 mm であった^[2階床位置の値。]。
```

- 保存する記法はPandocのインライン脚注 `^[本文]` です。本文は書式なしの1段落（2000文字以内）で、強調などの書式は取り除いて文字だけを保持します。
- GitHubなどの参照形式（`本文[^1]` と、別の行の `[^1]: 注の内容`）も読み込めます。読み込み後は `^[...]` に統一して保存し、定義行は本文に残しません。定義のない `[^1]` は通常の文字として扱います。どこからも参照されていない定義と、同じ名前で重複した定義は読み込まず、警告として行番号を表示します。
- 以前の版で保存した文書との互換のため、`^[文字](URL)`（`^` の直後のリンク）と `^[@label]`（`^` の直後の相互参照）は脚注として扱いません。脚注の中に脚注を入れ子にすることはできず、内側の `^[...]` は文字として残ります。
- 章別プロジェクトでは有効な章を通して採番します。ページ下端への固定や、ページをまたぐ脚注の分割は行いません。
- 発表者ノート内の脚注は採番せず、ノートの中に括弧書きで表示します。

## 注記ブロック

引用の先頭行に種類を書くと、色と見出しの付いた注記になります。ツールバーの **注記の種類** からも設定でき、「注記なし」で通常の引用に戻せます。記法はGitHubのアラートと同じです。

```markdown
> [!WARNING]
> 層間変形角が 1/100 を超える場合は再検討する。
```

種類は `NOTE`（注記）、`TIP`（ヒント）、`IMPORTANT`（重要）、`WARNING`（警告）、`CAUTION`（注意）の5つです。大文字・小文字は区別しません。種類は引用の最初の行に単独で書いてください。同じ行に本文を続けた場合や未知の種類は、通常の引用として扱います。

## 発表者ノート

Slide文書でツールバーの **発表者ノートを追加** を押すと、編集中のスライドの末尾にノート欄を追加します（すでにある場合はその欄へ移動します）。ノートは発表者だけが見る内容で、完成プレビュー、スライド本体、印刷／PDFには表示しません。HTMLスライドでは `N` キーで画面下に、`S` キーで発表者ビューに表示します。

```markdown
# 解析結果

::: notes
最初に結論を述べる。質問は最後に受ける。
:::
```

- `::: notes` と終了行の `:::` は文書直下に置きます。中に書けるのは段落だけです（見出し・リスト・図・表は不可）。ノート内にカーソルがある間は、見出し・リスト・引用・表などのボタンとショートカットは無効になります。
- ノートは、それが置かれたスライド（前後のスライド区切りの間）に属します。
- Report文書でも読み込み・保存できますが、出力には表示しません。

## Slideの図を自由に配置する

Slide文書では **図を配置** タブから画像を選び、16:9キャンバス上でドラッグ移動、8方向のハンドルによるリサイズ、矢印キーによる微調整を行えます。図を選択したときは移動、ハンドルにフォーカスしたときはリサイズとして矢印キーが働きます。配置済みの図は、通常の図の本文フロー配置とは別に、スライド上で重ねて表示されます。

座標は左上からの `x,y,width,height` をスライド全体に対するパーセントで保存します。Markdownで手編集する場合は図の直後に次の属性行を置きます。`slide_layout` はSlide文書の図だけに使用できます。

```markdown
![構成図](assets/diagram.png)
{slide_layout="12,18,40,30"}
```

Document JSON、完成プレビュー、単一HTML出力はこの情報を保持します。Markdown／JSONには画像本体を含めないため、再開時には原稿と元の画像ファイルを同時に選択してください。画像込みの単一文書ZIPなら元画像を再選択せずに開け、同名画像の入れ子パスも区別されます。章別プロジェクトは専用のプロジェクトZIPで保存します。HTML出力には取り込んだローカル画像を埋め込みます。

## 表の高度編集

ビジュアル編集で表セルを選択すると、表専用ツールバーから次を操作できます。

- 上下の行、左右の列の追加と削除
- 選択中の行のヘッダー行切替
- 隣接セルの結合と、結合済みセルの分割
- 全体・外側・内側・各辺の罫線。色、実線／破線／点線／二重線、太さの設定
- 同じ対象を選んだ罫線の消去

結合する範囲の同じ外周辺で罫線設定が異なる場合は、結合後に線分の情報を失わないよう、罫線を統一するまで結合できません。

通常の矩形表は標準のパイプ記法Markdownに保存します。結合セル、個別罫線、複数段落を持つセル、標準形式にできないヘッダー構成を含む表は、自動的にKUMIの可逆表ブロックへ保存します。このブロックは有効なJSONのまま残してください。手作業で原稿を調整する場合も、表の詳細編集はビジュアル編集で行い、Document JSONまたはプロジェクトZIPを原本として保存することを推奨します。

完成プレビューとSlideのHTML出力は、セル結合と個別罫線を表示します。外部の一般的なMarkdownビューアはKUMI表ブロックを標準表として表示できない場合があります。

## JSON互換

既存の「Markdownを開く」からDocument JSONも選択できます。画像を併せて選ぶ手順はMarkdownと同じです。schemaVersion 1と2を検証し、読み込み後とJSON保存時は2に移行します。未知のバージョンは拒否します。v1の本文・metadata・nodeIdを削除しません。

## 制限

ページ／スライド区切りは手動です。長い本文の自動ページ割り、厳密なA4高さ、PDF出力は提供していません。長い内容は区切りを追加してください。

Slide文書はヘッダーの「HTML」から、単体ブラウザで開けるスライドとして出力できます。番号・目次・参照・脚注・テーマを共通の描画処理で保持し、スライド送り、一覧表示、発表者ノート／発表者ビュー、画面サイズに合わせた枠の縮小・拡大に対応します。本文を自動的に小さくして詰め込む機能ではありません。Reportと章別プロジェクトも単一HTMLへ出力でき、ブラウザで印刷／PDF保存できます。画像の扱い・操作・原稿保存の注意は [かんたんガイド](./quick-start.ja.md#htmlスライドを持ち出す) を参照してください。

### 検索・置換とグラフ

ヘッダーの虫眼鏡、またはビジュアル編集中の `Ctrl`／`Cmd`＋`F` から選択中の文書・章を検索し、前後の移動、1件置換、全件置換を実行できます。コードブロックとインラインコードは対象外です。未適用のMarkdown下書きがある間は置換がロックされます。置換はUndoできます。検索欄は `Esc` で閉じます。

編集画面の右上には、編集中の文書・章の文字数（英語表示では語数も）を表示します。本文と脚注を数え、数式・キャプション・グラフのデータ・発表者ノートは含めません。

ツールバーの **グラフを挿入** で折れ線・散布図・棒グラフを挿入します。グラフを選択し、右のプロパティでラベル、x/y値、軸、凡例、幅、キャプション、代替テキストを編集します。データは「ラベル,x,y」を1行ずつ入力します。Markdownでは `::: kumi-chart` の可逆JSONブロックとして保存し、Document JSONとZIPでも再編集できます。描画にはオフラインで同じSVGを使います。

### Reportの印刷と自動改ページ

Report HTMLの `@page` に用紙寸法を反映し、明示的な改ページを保ちます。ブラウザの標準印刷は長い本文を自動的に分割しますが、表・図・フッターの位置を厳密に組版する保証はありません。Paged.jsは表の分割と既存のCSSとの整合を追加検証する必要があるため、今回の実装には採用していません。長い章は印刷プレビューで確認してください。

KaTeXは数式表示を担当し、LaTeX文書クラス・任意パッケージ・TeXコンパイル・完全な`.tex`互換は対象外です。
